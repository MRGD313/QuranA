# کار بهینه با عامل هوش مصنوعی

این سند از اندازه‌گیری واقعی جلسهٔ ساخت نسخهٔ ۰.۱.۰ به دست آمده است: ۲۲۶ پیام،
۲۰۱ گام مدل، ۲۱٫۶ میلیون توکن context و ~۰٫۸۷ دلار هزینه. نتیجهٔ اصلی:
**هزینه ≈ تعداد گام × حجم context هر گام**؛ خروجی ابزارها کمتر از ۱٪ هزینه بود.
پس بهینه‌سازی یعنی «گام کمتر و context کوچک‌تر»، نه پاسخ کوتاه‌تر.

پیکربندی عملی این مخزن در دو فایل است و همین‌جا تکرار نمی‌شود:

- [`AGENTS.md`](../AGENTS.md) — دستورها، نقشهٔ کد، قواعد و ممنوعیت‌ها (هر جلسه خوانده می‌شود).
- [`opencode.jsonc`](../opencode.jsonc) — compaction، محدودیت خروجی ابزار، ignore داده‌های حجیم و deny خواندن `.env`.
- [`.opencode/commands/verify.md`](../.opencode/commands/verify.md) — یک دستور برای آزمون + بهداشت مخزن.

## اصول کلیدی

1. **هر جلسه یک کار.** context فقط رشد می‌کند؛ برای کار مستقل، جلسهٔ نو با یک خلاصهٔ کوتاه.
2. **`AGENTS.md` لاغر.** فقط چیزهایی که از کد پیدا نمی‌شود: دستورها، معیار پذیرش، ممنوعیت‌ها.
3. **افشای تدریجی.** جزئیات کاری در command/skill، نه در `AGENTS.md`.
4. **`grep`/`glob` قبل از `read`.** فایل بزرگ را با offset/limit بخوان؛ هیچ فایل >۲۰۰ خط را کامل نخوان.
5. **زیرعامل برای اکتشاف، نه نوشتن.** جست‌وجو و نقشه‌برداری در context جدا؛ فقط نتیجه برگردد.
6. **دسته‌بندی درخواست‌ها.** یک پیام با فهرست کارها بهتر از پنج پیام پیاپی است.
7. **تأیید با اجرا.** خروجی `pytest` را بخوان، نه اینکه کل فایل را دوباره مرور کنی.
8. **پایداری پیشوند.** `AGENTS.md` و config را قبل از شروع کار نهایی کن؛ تغییر وسط کار، prompt cache را باطل می‌کند.
9. **ابزار کم.** هر MCP/ابزار اضافه در هر درخواست تعریف می‌شود؛ بی‌استفاده‌ها را ببند.
10. **ابزارها را محدود کن.** deny خواندن `.venv/`، `data/raw/`، `data/*.db`، `data/reports/` و `.env`.

## چک‌لیست

**قبل:** کار را در یک جمله + معیار پذیرش بنویس؛ `git status` تمیز؛ داده آماده
(`data/quran.db`) وگرنه تست‌ها skip می‌شوند؛ جلسه و مدل مناسب.

**در حین:** اول جست‌وجو، بعد خواندن بازه‌ای؛ کارهای مستقل را در یک `execute`
موازی کن؛ خروجی بزرگ را فیلتر کن؛ برای کاوش از زیرعامل استفاده کن؛ در ~۸۰٪
پنجره، compact یا پایان تسک.

**پایان:** `python -m pytest tests -q`، `python scripts/check_repo_hygiene.py`،
مرور `git diff --stat`، ثبت کارهای باقی‌مانده در issue/TODO.

## ضدالگوها

| ضدالگو | جایگزین |
|---|---|
| خواندن کل فایل برای یک تغییر | `grep` + `read` بازه‌ای |
| پرسش‌های کوچک پیاپی | یک پیام با فهرست کارها |
| بازخوانی مکرر یک URL | یک بار fetch + ارجاع به نتیجه |
| جلسهٔ بی‌پایان | بستن تسک و جلسهٔ نو |
| تغییر config وسط کار | تنظیم قبل از شروع |
| زیرعامل برای کار نوشتاری | زیرعامل فقط برای اکتشاف |

## سنجه‌ها

تعداد گام، میانگین context هر گام، نسبت cache read به ورودی تازه، هزینهٔ هر کار
(نه روزانه) و نرخ گام‌های خطادار. هدف واقع‌بینانه: نصف‌کردن هزینهٔ هر کار با
همان کیفیت.
